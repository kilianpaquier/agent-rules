# Code review

- Review only when asked. Never offer, suggest, or start one.
- Sub-agent review: pass the full diff (or changed file content) as context, not a summary.
- Review each modified file in full, not just the changed hunks. Catch inconsistencies, duplication, coherence issues.
- Focus:
  - Architecture and design: structure, abstraction boundaries, separation of concerns.
  - Bugs and functional correctness.
  - Security issues.
  - Adherence to project conventions.
  - Unnecessary complexity or duplication.
  - Documentation: missing or incorrect language-mandated comments (GoDoc, JSDoc).
- Skip generated, vendored, and third-party code (`vendor/`, `node_modules/`, `dist/`, `build/`, or files with `Code generated by` / `DO NOT EDIT` / `@generated` headers).
  Strip those hunks before passing the diff to a sub-agent.
- Flag dead or unreachable code as a finding.
- Same focus for test files. Check language-specific test conventions (*e.g.* the `*.instructions.md` rules for package naming, helper markers, phase comments).
