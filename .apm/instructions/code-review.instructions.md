# Code review

- Review only when asked. Never offer, suggest, or start one.
- For a sub-agent review, pass the full diff (or the changed file content) as context, not a summary.
- Review each modified file in full, not just the changed hunks. Catch inconsistencies, duplication, and coherence issues.
- Focus on:
  - Architecture and design: structure, abstraction boundaries, separation of concerns.
  - Bugs and functional correctness.
  - Security issues.
  - Adherence to project conventions.
  - Unnecessary complexity or duplication.
  - Documentation: missing or incorrect language-mandated comments (GoDoc, JSDoc).
- Skip vendored and third-party code (`vendor/`, `node_modules/`, `dist/`, `build/`).
- Skip deterministic generator output, marked `DO NOT EDIT`, `@generated`, or `Code generated by <tool>`.
- Never skip a file marked `Code generated by AI`, it needs the same review as hand-written code.
- Strip skipped hunks before passing the diff to a sub-agent.
- Flag dead or unreachable code as a finding.
- Keep the same focus for test files. Check language-specific test conventions (*e.g.* the `*.instructions.md` rules for package naming, helper markers, phase comments).
